Eigene IEC-104-Library in C/C++

Kern in C++17 mit stabiler C-API, jede Abweichung der Gegenstelle als Parameter, TLS über OpenSSL. Erster Einsatz: Anbindung an die Prozessabkopplung (Aucoteam).

Grundlage: Konzeptdokument „Konzept IEC-104-Library (C/C++)“ und Recherchebericht „IEC 104 im Detail“.

Ziel und Rahmen

Client und Server für die SpPS, Normverhalten als Default

Version 1

Umfang

Client und Server, alle Monitor-, Steuer-, System- und Parametertypen, Redundanzgruppen (Ed. 2), TLS nach IEC 62351-3.

Später

Ausbau

Dateiübertragung (Typen 120–127), Secure Authentication nach IEC TS 60870-5-7, IEC 101 seriell.

Leitprinzip

Parameter statt Sonderfall

Jede bekannte Abweichung einer Gegenstelle ist ein Parameter, nie ein Code-Zweig für einen Hersteller.

  • Normbasis: IEC 60870-5-104 Ed. 2.1 (2006 + AMD1:2016) inkl. COR1:2023
  • Schnittstelle: stabile C-API, für Rust über bindgen, optional C++-Wrapper
  • Lizenz: Eigenentwicklung ohne GPL-Code; lib60870-C nur als Testgegenstelle

TLS

Externe Library hinter schmaler Backend-Schnittstelle

Erstes Backend

OpenSSL 3.x

Apache 2.0, TLS 1.2 und 1.3, sichere Renegotiation, Standard auf Linux-Servern.

Alternative

mbedTLS 3.x

Apache 2.0, TLS 1.2 und 1.3, Renegotiation per Build-Option, eher für schlanke Ziele.

  • Profil nach IEC 62351-3 Ed. 2 (2023): TLS 1.2/1.3 einzeln abschaltbar, Cipher-Liste je Verbindung
  • Gegenseitige X.509-Authentifizierung, CRL und optional OCSP, Zertifikatswechsel ohne Neustart
  • Renegotiation bzw. Key Update nach Zeit oder Datenmenge, Session Resumption konfigurierbar
  • Sicherheitsereignisse als Callback, angelehnt an IEC 62351-14

Grund: Laut BDEW-Whitepaper 3.0 hat IEC 104 ohne Zusatzmaßnahmen weder Integrität noch Authentifizierung noch Verschlüsselung.

Laufzeitmodell

Eigener Event-Loop oder vom Host getaktet

Betrieb

Zwei Betriebsarten

Interner Thread je Instanz oder Host ruft iec104_poll(timeout). I/O über poll/epoll, keine Async-Bibliothek nötig.

Threads

Klare Regeln

Senden aus jedem Thread über interne Queue. Callbacks immer aus dem Loop-Thread.

Zeit

Injizierbare Uhren

Monotone Uhr für Timer, Wanduhr für Zeitstempel. Beide austauschbar, wichtig für Tests.

Fehler

Returncodes

Protokollverletzungen je nach Konfiguration: negative Quittung, Ereignis oder Verbindungsabbau.

Diagnose

Logging und Statistik

Log-Callback mit Level, optionaler Hexdump je APDU, Zähler je Verbindung.

Speicher

Begrenzt

Puffer vorab allokiert, Obergrenzen konfigurierbar, keine unbegrenzten Queues.
